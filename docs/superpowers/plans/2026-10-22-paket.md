## Global Constraints

- UI text German in `Strings.resx`; code comments English, matching surrounding density; colors from existing CSS variables.
- Files of the vault change only where the design says so; unchanged saves stay byte-identical.
- UI settings persist in `UiSettings` (pattern of `HideUsed`/`ShowCoverage`), clamped/validated on load.
- bUnit: `WaitForAssertion`/`WaitForElement` after state changes; poll session state that is not tied to a render with a real-time loop (see `CoverageTabTests.Eventually`).
- Commits: `git commit -F <file>`; each message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. SDK env (PowerShell): `$env:DOTNET_ROOT="$env:LOCALAPPDATA\Microsoft\dotnet"; $env:PATH="$env:DOTNET_ROOT;$env:PATH"`.
- Never kill processes you did not start; never touch master or other worktrees.

### Task 4: Per-day journal markers and filters

**Design:**
- Every day card in the journal has two checkboxes at its top right: "nicht relevant" and "später". They are independent.
- "nicht relevant" applies to the currently selected book. It is stored as a page property of the day's journal file, `not-relevant-for:: [[<book link name>]], [[<other book>]]`, with one entry per book; the format is like `used-in`. Unchecking removes only this book's entry, and removes the property when it becomes empty.
- Without a selected book the "nicht relevant" checkbox is disabled.
- "später" applies to every book. It is stored as `later:: true` and removed when unchecked.
- The file is written through the normal page writer: backup, self-write registry, read-only page refused with the usual message, conflicts as for other note writes.
- Filters: the journal gets two checkboxes next to "Verwendete ausblenden": "‚nicht relevant' ausblenden" (for the current book) and "‚später' ausblenden". Both are persisted in `UiSettings` and restored on start.
- The "Von"/"Bis" filter is commented out in the markup (not deleted) and has no effect while commented out. "Springen zum Tag" stays.
- Search and Relevant are not affected.

**Files:**
- `src/NoteEvolution.UI/Components/JournalTab.razor`, `NotesPane.razor`
- `src/NoteEvolution.Core` page-property helper if one is needed (parsing the `[[…]]` list can reuse `UsedInValue`-style parsing)
- `UiSettings.cs`, `Strings.resx`, `app.css`
- Tests: Core (property parse/format and toggle), UI (`NotesPaneTests`/Journal tests)

- [ ] Tests first:
  - Checking writes the property.
  - Unchecking restores the file byte-identically (Review Focus 1).
  - Two books keep each other's entries (Review Focus 2).
  - "später" is independent of "nicht relevant".
  - The checkbox is disabled without a book.
  - A read-only file shows the message and nothing changes.
  - The filters hide the right days and are persisted.
  - Von/Bis are no longer rendered.
- [ ] Implement, run all tests, commit "feat: journal days can be marked not relevant or later, with filters".

### Task 6: Grouped "Zuletzt geändert"

**Design:**
- When several text blocks of the same heading section were last changed on the same day, the list shows one entry for them instead of one per block:
  - the heading's path,
  - the latest time,
  - the summary sentence of the section (else the first block's excerpt),
  - "N Blöcke".
- A click on a grouped entry goes to the heading.
- Single blocks appear as before.
- The limit of 20 counts entries, not blocks.
- "Same section" means the block's own section (its nearest heading), not ancestors.
- Prologue blocks (root) group under the book title as path; their click goes to the first of them.

**Files:**
