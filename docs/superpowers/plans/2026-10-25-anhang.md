# Anhang (Glossar, Menschen, Quellen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drei Anhang-Abschnitte am Buchende: Glossar, Menschen, Quellen.
- Sie werden in Fenstern bearbeitet.
- Im Text stehen Verweise darauf: ein Kürzel für Menschen, eine Nummer für Quellen, eine automatische Markierung für das Glossar.
- Im Editor und im PDF werden sie dezent dargestellt.

**Architecture:**
- **Erkennung:** Die Anhang-Abschnitte sind gewöhnliche Überschriften der obersten Ebene mit `anhang::`. Ihre Einträge sind Textblöcke darunter.
- **Ausschluss:** `Book` erkennt die Abschnitte. Alle Verbraucher, die den Buchtext meinen, filtern sie über eine einzige Stelle (`Book.ContentChildren`) heraus.
- **Speichern:** Editor-Speichern und `BookSync` lassen die Abschnitte unberührt.
- **Verweise:**
  - Menschen: gewöhnliche Blockverweise `((id))`.
  - Quellen: Makros `{{quelle ((id)) Fundstelle}}`.
  - Glossar: keine Änderung am Text; die Treffer berechnet `AppendixIndex` jedes Mal neu.

**Tech Stack:** .NET 10, Blazor Hybrid, xUnit + bUnit, TipTap/ProseMirror (esbuild-Bundle, jsdom-Tests), QuestPDF.

**Spec:** `docs/superpowers/specs/2026-10-25-anhang-design.md`

## Global Constraints

- **Umgebung:**
  - .NET: `$env:DOTNET_ROOT="$env:LOCALAPPDATA\Microsoft\dotnet"; $env:PATH="$env:DOTNET_ROOT;$env:PATH"`, dann `dotnet test` im Worktree-Root.
  - Editor: `npm run build` und `npm test` in `src/NoteEvolution.UI/Editor/js`. Das Bundle wird nach jeder Änderung an `editor.js` neu gebaut und mit committet.
- **Bestehende Suite bleibt grün:** Core 837, Pdf 40, AI 305 + 1 übersprungen, UI 791. Ein Buch ohne Anhang verhält sich in allem wie heute.
- **Eigenschaften:**
  - `anhang:: glossar`, `anhang:: menschen`, `anhang:: quellen`
  - `formen::`, `kuerzel::`, `themen::`, `art::` (`buch|video|artikel|webseite|sonstiges`), `autoren::`, `jahr::`, `url::`, `herausgeber::`
- **Standardtitel:** „Glossar“, „Menschen, die mich inspiriert haben“, „Quellen“. Die Reihenfolge am Buchende ist Glossar, Menschen, Quellen.
- **Kürzel:** 1–6 Zeichen aus Buchstaben, Ziffern, `.` und `-`, eindeutig im Buch ohne Rücksicht auf Groß- und Kleinschreibung. Der Vorschlag besteht aus den Initialen der Namensteile in Großbuchstaben; bei einer Kollision wird eine Ziffer angehängt, ab 2.
- **Quellenmakro:** `{{quelle ((id))}}` bzw. `{{quelle ((id)) Fundstelle}}`.
- **Lesereihenfolge des PDFs:**
  - Überschriften und Textblöcke in Buchreihenfolge.
  - Ohne Blöcke mit Status Relevant oder Bemerkung samt ihren Details.
  - Ohne den Anhang.
- **Texte** auf Deutsch in `Strings.resx`. Kommentare im Code auf Englisch im Stil der Dateien.
- **Commits** enden mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Editor-Speichern bei vorhandenem Anhang:** Wer im Editor tippt und speichert, darf den Anhang nicht löschen, verschieben oder neu datieren. Das ist das Wichtigste. → Test in Task 1.
2. **Neue Abschnitte bei vorhandenem Anhang:** „+ Abschnitt“ in der Gliederung, „Neuer Abschnitt danach“ auf dem letzten Abschnitt, „Als Überschrift“ und Ziehen ans Ende landen vor dem Anhang. → Test in Task 1.
3. **Ein in Logseq bearbeiteter Anhang:**
   - Eintrag ohne `id::` bekommt beim ersten Speichern durch die App eine; der Eintrag bleibt.
   - Unbekannte Eigenschaften bleiben.
   - Doppelte Kürzel werden gemeldet, nicht gelöscht.

   → Tests in Task 2 und Task 8.
4. **Glossar-Treffer an Rändern:**
   - Ein Begriff mitten im Wort ist kein Treffer.
   - Ein Treffer nach Satzzeichen oder am Absatzende zählt.
   - Umlaute zählen als Buchstaben.
   - In Verweis-Elementen gibt es keinen Treffer.
   - Bei zwei überlappenden Formen gilt die längere.

   → Tests in Task 3.
5. **Löschen eines Menschen, der Autor einer Quelle ist:** Die Quelle bleibt, ihr Autorverweis wird zu „Verweis fehlt“, und die Rückfrage nennt die Zahl. → Test in Task 5.
