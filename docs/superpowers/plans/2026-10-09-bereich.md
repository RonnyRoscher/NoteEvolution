# Range, Targets and Merging (Package B) – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The marked range can be widened and narrowed level by level, and "Relevant", sources, "Zusammenfügen" and "Unter neue Überschrift" follow it. "Wohin damit?" lists matching text blocks for a note or a sub-bullet, jumps there and adopts there.

**Architecture:**
- **Range in Core:** `BookRanges` computes the range from the book tree: the marked editor nodes, the text blocks, the topic section and the merge groups.
- **Editor:** The editor no longer computes the box itself; the UI pushes the marked nodes to it.
- **Merge and wrap in Core:** Merge is a link-aware `LinkService` operation. "Unter neue Überschrift" is a `ManuscriptEditor` operation with its own undo object, like `RemovedHeading`. `ManuscriptCommands` runs both like the package-A commands.

**Tech Stack:** .NET 10, Blazor Hybrid (Photino), TipTap 2.27 (esbuild bundle), xUnit + bUnit.

**Spec:** `docs/superpowers/specs/2026-10-09-bereich-design.md`. Read it first. It builds on package A (`docs/superpowers/specs/2026-10-08-manuskript-design.md`).

**Interfaces (produces):**

```csharp
namespace NoteEvolution.Core.Books;
/// <summary>An editor node to mark: a heading, a text block or a detail (paragraph) key.</summary>
/// <param name="OwnTextOnly">Text block: only its own text, without details. Detail: only this paragraph, without deeper ones.</param>
public sealed record MarkedNode(Guid Key, bool OwnTextOnly);

/// <param name="Head">The element that defines the range; null = the whole book (root).</param>
/// <param name="Level">-1, 0, 1, …</param>
/// <param name="Nodes">The nodes to mark, in document order.</param>
/// <param name="TextBlockKeys">The text blocks in the range (for the topic and the sources), in file order.</param>
/// <param name="SectionKey">The heading whose path names the topic: the head itself, or the head's section; Guid.Empty for the prologue or the whole book.</param>
/// <param name="MergeGroups">For every heading (or the root) in the range: its own text blocks in the range, in file order; only groups with ≥ 2 blocks.</param>
public sealed record RangeInfo(BookElement? Head, int Level, IReadOnlyList<MarkedNode> Nodes,
    IReadOnlyList<Guid> TextBlockKeys, Guid SectionKey, IReadOnlyList<IReadOnlyList<Guid>> MergeGroups);

public static class BookRanges
{
    /// <summary>The range of level <paramref name="level"/> around <paramref name="cursor"/>; level is clamped to [-1, MaxLevel].</summary>
    public static RangeInfo Of(Book book, BookElement cursor, int level);
    /// <summary>The level whose head is the whole book (the number of ancestors of the cursor element up to the root).</summary>
    public static int MaxLevel(Book book, BookElement cursor);
}
```

**Semantics (spec section 1, "Begriffe", and section 2):**
- **Ancestors:**
  - of a detail: its parent detail(s), then its text block, then the headings up to the root;
  - of a text block: its heading(s);
  - of a heading: its parent heading(s).
- **Level 0:** the head with everything below it.
  - Heading: the heading node, plus all its text blocks (whole), sub-headings and their text blocks, recursively.
  - Text block: the node, whole.
  - Detail: the detail node, not own-only; that includes its deeper paragraphs.
- **Level −1:**
  - Heading: the heading plus only its own text blocks (whole).
  - Text block: `MarkedNode(tb, OwnTextOnly: true)`.
  - Detail: `MarkedNode(detail, OwnTextOnly: true)`.
- **Level ≥ 1:** the k-th ancestor as head, at level 0.
  - At MaxLevel the head is null (the root), and the nodes are every heading and text block of the book.
- **TextBlockKeys:**
  - all text blocks covered by the nodes;
  - for a detail range, its text block;
  - for level −1 on a heading, only its own text blocks.
- **SectionKey:**
  - head heading → its key;
  - head text block or detail → `BookElements.SectionOf`;
  - root → `Guid.Empty`.

### Task 2: Core – merge text blocks with their links

**Files:**
- Modify: `src/NoteEvolution.Core/Links/ILinkService.cs`, `src/NoteEvolution.Core/Links/LinkService.cs`
- Test: `tests/NoteEvolution.Core.Tests/Links/MergeTests.cs`

**Interfaces (produces):**
- `Guid ILinkService.MergeTextBlocks(Book book, IReadOnlyList<IReadOnlyList<Guid>> groups)`. It returns the key of the first remaining block of the first group. It pushes one undo action, „Zusammenfügen“.
- `ArgumentException` for an unknown key, for a group with fewer than 2 blocks, or for blocks of one group that do not share the same parent block. `ReadOnlyPageException` for a read-only book.

**Semantics** (spec section 4), per group:
- **First block:** its content becomes `first + "\n\n" + next + "\n\n" + …`. Each content is used as stored; property lines are not content.
- **Details:** the detail blocks of the later blocks are moved, in order, behind the first block's children.
- **Removed blocks:** the later blocks are removed.
- **`source::`:** the union of all `source::` values, in first-seen order. `id::` of the first block, set if any later block was linked.
- **Notes:**
  - every note whose `used-in::` references a removed block's id is rewritten to the first block's id;
  - an entry that would duplicate one already present for the first block is removed instead.
- **Write order:** book first, then notes; pending on note failure, as in `Adopt`.
- **Undo:**
  - **book:** restore it with the `PageStructureSnapshot` taken before; refuse if the page no longer `Matches` the after-state;
  - **notes:** each note goes back to its `Before` lines if it is still exactly as the merge left it; otherwise the original usage entries are re-added, as in `UndoDelete`'s `NoteChange` handling.

### Task 3: Core – "Unter neue Überschrift"

**Files:**
- Create: `src/NoteEvolution.Core/Books/WrappedSection.cs`
- Modify: `src/NoteEvolution.Core/Books/ManuscriptEditor.cs`
- Test: `tests/NoteEvolution.Core.Tests/Books/WrapTests.cs`

**Interfaces (produces):**

```csharp
// ManuscriptEditor:
public static bool CanWrap(Book book, BookElement head);           // false for a detail, the root (no head) and when a heading would exceed level 6
public static WrappedSection Wrap(Book book, BookElement head);   // ArgumentException when !CanWrap; changes book.Page in memory
// WrappedSection (same pattern as RemovedHeading):
public Guid NewHeadingKey { get; }
public bool CanRestore(Book book);
public void RestoreInto(Book book);
```

**Semantics** (spec section 5):
- **Placement:** S is the section of the head; the new heading N gets level S.Level + 1 and an empty title (`- # `-style, as in package A), at the head's index in S's children.
- **Heading head:** the head heading block, with its whole subtree, becomes N's first child and is releveled one deeper, with all its sub-headings.
- **Text block head:** the head and every following own text block of S (in file order, up to S's end, skipping S's sub-headings, which stay with S) become N's children, in order.
- **Undo (`RestoreInto`):**
  - removes N and moves the moved blocks back under S at their original indices;
  - restores the moved headings' original levels; their text and any title edits inside them are kept, and N's title is dropped;
  - `CanRestore` is false if N is gone, or if any moved block (or any block of the moved subtrees) no longer has the parent it was left with. This is the same rule as `RemovedHeading` after its fix.
  - Byte-exact when nothing changed since.
